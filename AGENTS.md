# AGENTS.md

Timber Acoustics marketing site: TanStack Start + React 19 + Tailwind v4 + shadcn/ui, single package (no monorepo).

## Commands (all verified)

- `npm i` — install. Both `package-lock.json` and `bun.lock` are committed; use **npm** locally (README/`node_modules` agree). `bun.lock` pins `@lovable.dev/*` to Lovable's private sandbox registry URL, and `bunfig.toml` enforces a 24h `minimumReleaseAge` — adding to `minimumReleaseAgeExcludes` needs user confirmation.
- `npm run dev` — Vite dev server (SSR). Prefers port **8080**, auto-increments if busy.
- `npm test` — `vitest run` (jsdom). Single file: `npx vitest run src/test/app-routing.test.tsx`.
- `npm run lint` — ESLint with prettier formatting as **errors**. The committed baseline currently fails lint with `prettier/prettier` errors in files you didn't touch; run `npm run format` (or `eslint --fix`) and only fix the files you changed.
- `npx tsc --noEmit` — typecheck; there is no `typecheck` script. Passes at HEAD.
- `npm run build` — nitro build to `.output` (Cloudflare target). `.output`, `.wrangler`, `.vinxi` are gitignored. No CI workflows exist, so verify locally.
- Suggested order before finishing: `npm run format` → `npm run lint` → `npx tsc --noEmit` → `npm test`.

## Vite config — do not duplicate plugins

`vite.config.ts` calls `defineConfig` from `@lovable.dev/vite-tanstack-config`, which already includes tanstackStart, viteReact, tailwindcss, tsConfigPaths, nitro, `VITE_*` env injection, the `@/` alias, React dedupe, error loggers, and dev sandbox port/host detection. Adding those manually breaks the app with duplicate plugins; pass extras through the existing `defineConfig({ vite: {...} })` shape.

## Routing

- File-based routes in `src/routes/`; the URL conventions table lives in `src/routes/README.md` — follow it (bare `$` params, `__root.tsx` is the only root layout; no `src/pages/`, no Next/Remix layouts).
- `src/routeTree.gen.ts` is generated by the router plugin during `vite dev`/`vite build`. It is committed — never hand-edit.
- `src/routes/__root.tsx` must keep `<Outlet />` and uses `shellComponent` + `component`; links use typed params (`<Link to="/products/$slug" params={{ slug }}>`).

## Server / SSR quirks (keep these files intact)

- `vite.config.ts` sets `tanstackStart.server.entry = "server"` → `src/server.ts` wraps the SSR entry to convert h3-swallowed failures (`{"unhandled":true,"message":"HTTPError"}` + JSON content type) into the HTML 500 page.
- `src/start.ts` defines `createStart(...)`. Creating this file opts out of TanStack's auto-installed start instance, so it re-adds the CSRF middleware for server functions — do not remove it.
- ESLint bans the Next.js `server-only` package; name server modules `*.server.ts` or import `@tanstack/react-start/server-only`.
- `three` is dynamically `import()`ed behind an `import.meta.env.SSR` guard in `src/components/site/AcousticCanvas.tsx`; keep WebGL/browser-only work out of the server render.

## Testing

- Vitest + jsdom + Testing Library; setup file `src/test/setup.ts` (stubs `matchMedia`/`scrollTo`) — stub new browser APIs there.
- Include pattern `src/**/*.{test,spec}.{ts,tsx}`; tests live under `src/`. Only `src/test/app-routing.test.tsx` exists.

## Content and tsconfig gotchas

- `src/data/*.ts` is placeholder/demo content (products, copy) and pages label prices/specs as demo; the cart (`src/lib/cart.tsx`) is in-memory only and the contact form sends nothing. Don't treat it as real business data.
- tsconfig is strict with `noUncheckedIndexedAccess`, `exactOptionalPropertyTypes`, `noPropertyAccessFromIndexSignature` **on** (easy to trip), while `noUnusedLocals`/`noUnusedParameters` are **off**. `@/` maps to `src/`.
